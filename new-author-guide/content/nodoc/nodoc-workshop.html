Introduction · NoDoc platformWorkshop orientation

NoDoc is an Oracle APEX documentation workbench for creating, organizing, reviewing, improving, ingesting, and preparing technical content for publication. This workshop follows the LiveLabs author journey: select the right Focus Area, create an article and version, build focused pages, review changes, validate the preview, then use the existing WMS publishing request path. Choose one creation route and one page route for the required path; use the other routes as reference.

Prerequisites

  • Oracle SSO access to the NoDoc environment.
  • A NoDoc role that permits the authoring, comment, or review actions you will practice; deletion remains limited to the comment owner and roles with that privilege.
  • An approved practice article or page set in the LiveLabs Focus Area. Use non-confidential content for ingestion and AI-assisted review.

Objectives

  • Navigate NoDoc and select the correct Focus Area.
  • Create an article, version, and page set for a documentation topic.
  • Edit content, apply metadata, and use supported editor features.
  • Collaborate with comments and draft review without overwriting original content accidentally.
  • Validate and correct content with Vibe Doc-ing using standards, personas, custom prompts, and the approved Word-Checklist, with explicit human review.
  • Ingest and query approved content with Ask NoDoc while inspecting source context.
  • Complete Quality Assurance and review before creating the WMS publishing request.

Lab 3 · Edit and organize page content

After the article and page structure exist, prepare each page for authoring. Set the saving behavior, apply approved metadata, write structured LiveLabs content, and use drafts when proposing changes to pages owned by another author.

Objectives

  • Choose the appropriate Autosave behavior and confirm the saved state.
  • Create a draft without changing the original page, then review and approve or reject its changes.
  • Apply approved metadata tags and intentional filter tags.
  • Write, format, save, and inspect structured page content.
Task 1 · Control Autosave
  1. Use the Autosave toggle in the page toolbar to choose whether NoDoc saves progress automatically.
  2. Turn Autosave ON when you want automatic progress saves. The current UI confirms that it runs every two minutes; when Autosave is OFF, automatic saves are disabled.
  3. Before leaving the page, confirm the saved state. Owners use Save to update the original; non-owners use Save Draft for owner review.
Task 2 · Create and manage page drafts

Use a draft to propose changes to a page owned by another author. The original page remains unchanged while you edit the draft. After you save it, review the draft history and compare the draft with the original before approving or rejecting the proposed changes.

  1. From the article or workshop list, select a page from content created by another author, then select Edit. When NoDoc asks whether to create or continue a draft, verify the selected page and choose the affirmative option. In the captured state, an existing draft is detected and that option is labeled OK. This opens the draft editing flow without changing the original page.
  2. Confirm that the Edit Draft window opens. Read the warning that changes will not modify the original page, then verify the original topic name and draft topic name.
  3. Edit the draft content in the rich-text editor. When the proposed content is ready to save, select Save Draft and confirm the success message Draft Saved Successfully.
  4. To review a saved draft, select Drafts on the article page. In the Draft Version window, review the draft table, including the draft name, editor, date, status, age, and content size. Select View Diff for the draft you want to inspect.
  5. In the Draft Difference Viewer, compare the original content on the left with the draft on the right. Use Prev Change and Next Change to move through the differences. For each change, select the green check to accept it or the red X to reject it. When the review is complete, select Approve to apply the accepted draft changes.

Task 4 · Write structured content
  1. Open the target page and select Edit.
  2. Confirm editing is enabled: the editor toolbar and Save & Check In are visible.
  3. Use the toolbar to build or revise the page. Start with a concise introduction, objectives, prerequisites when needed, then headings and numbered learner tasks.
    • Heading sets the page structure.
    • Bold, Italic, and Strikethrough apply emphasis or mark text for removal.
    • Quote and Note separate quoted material, warnings, decisions, or context.
    • Code block adds copyable code; Tabs separate different content; Quiz adds a knowledge check; Inline code formats commands or tokens.
    • Image and Link add approved media with alt text and tested relative links; Indent/Outdent changes block nesting.
    • Video, Table, and Lists add media, structured data, and learner steps; MD Source lets you inspect or edit the Markdown source.
  4. Click Save & Check In to save progress manually, then review the rendered content, links, images, and page position.

Lab 6 · Vibe Doc-ing content validation and corrections30 minutes

Vibe Doc-ing is NoDoc's review workspace for checking and correcting existing page content. It applies one selected validation mode to the page you opened, returns proposed content, and lets you compare that proposal with the current version before you accept it.

Reach it from the upper action row on a saved NoDoc page. Use one option at a time: start with the built-in standards review, choose a persona when the review needs a specific audience or structure, write a Custom Prompt when the correction is unique, or use Word-Checklist for approved terminology corrections. Vibe Doc-ing proposes changes; it does not publish, ingest, or replace the source until you review the output and Difference view.

After the workshop content is complete and accepted corrections are saved, use the final task to generate the article-level Information Map from the workshop's lab titles and page content for SEO and AI-search discovery.

Objectives

  • Open Vibe Doc-ing on the correct saved page and understand the four validation options.
  • Run one option, inspect its proposed output, and compare it with the current version.
  • Accept only changes that match the review scope and preserve technical content.
  • Generate and save the article-level Information Map after the workshop content is complete.

Lab 8 · Pre Publish and validation results25 minutes

Use Pre Publish after the NoDoc page and article are saved. Configure the LiveLabs target, create the Sandbox and/or Tenancy URLs you need, run both mandatory validations, and inspect each result before deciding whether to correct findings or continue with an approved exception.

Flow: Configure the target and URLs → run Markdown and Text Check validations → inspect findings → correct and rerun when needed → acknowledge remaining findings only when authorized → use Preview, Push, or Download Zip.

Objectives

  • Complete the LiveLabs Pre Publish details and create the URLs required for the workshop.
  • Run and inspect both mandatory validation sets, then use Vibe Doc-ing to correct flagged content when needed.
  • Choose the correct post-validation output: Preview, Push, or Download Zip.
Task 1 · Configure the LiveLabs Pre Publish target
  1. From the saved NoDoc article, click the Pre Publish button in the upper action row, then select the LiveLabs tab.
  2. Fill in the LiveLab, Version, Content Area, and Workshop fields. In Workshop Types, select Sandbox, Tenancy, or both according to the environments the workshop requires.
  3. Select Create URL. Copy the generated Sandbox URL, Tenancy URL, or both into the review record that will accompany the QA handoff.
Task 2 · Run mandatory validations and resolve findings
  1. Select Run Markdown Validations. Review the Markdown result table by severity, page, rule code, message, and status; use it to locate structural or formatting defects.
  2. Select Run Text Check Validations. Review the Text Check result table separately; do not assume a successful Markdown run covers grammar, protected text, or wording findings.
  3. For each flagged page, decide whether the finding is valid. When content needs correction, return to Vibe Doc-ing and use the narrowest suitable option: Apply Standards, Persona Prompt, Custom Prompt, or Word-Checklist. Review Output and Difference, save the accepted correction, and rerun the relevant validation.
  4. If findings remain after the correction pass, select Pre Publish to see the confirmation warning. Choose Cancel to continue fixing content, or choose OK only when the remaining findings are understood, approved, and recorded for review.
Task 3 · Choose the post-validation output
  1. After Pre Publish completes, review the available actions: Preview, Push, and Download Zip.
  2. Select Preview to open the generated workshop and inspect the rendered result before any release action.
  3. Push is available from this dialog, but availability is not approval. Complete the QA and review gates in Lab 9 first, then return here and select Push when your role is authorized to publish the content. Confirm the success response before creating the WMS publishing request.
  4. Select Download Zip to save the workshop archive for review, handoff, or recovery. Keep the archive with the QA evidence when the release process requires it.
