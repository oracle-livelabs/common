Introduction · NoDoc platformWorkshop orientation

NoDoc is an Oracle APEX documentation workbench for creating, organizing, reviewing, improving, ingesting, and preparing technical content for publication. This workshop follows the LiveLabs author journey: select the right Focus Area, create an article and version, build focused pages, review changes, validate the preview, then use the existing WMS publishing request path.

Prerequisites

  • Oracle SSO access to the NoDoc environment.
  • A NoDoc role: CONTRIBUTOR for authoring or READER for review-only activities.
  • The assigned LiveLabs Focus Area and approved source material for the workshop.

Objectives

  • Navigate NoDoc and select the correct Focus Area.
  • Create an article, version, and page set for a documentation topic.
  • Edit content, apply metadata, and use supported editor features.
  • Collaborate with comments and draft review without overwriting original content accidentally.
  • Apply AI-assisted correction and generate an article information map with explicit human review.
  • Ingest and query approved content with Ask NoDoc while inspecting source context.
  • Complete Quality Assurance and review before creating the WMS publishing request.

Objectives

  • Navigate the NoDoc platform.

  1. Open the approved NoDoc environment. Open NoDocRequires Oracle VPN and NoDoc access.
  2. Sign in through Oracle SSO. If the stage environment requests a bypass code, obtain it through the approved manager process; do not paste codes into workshop artifacts.
  3. Choose the NoDoc application.
  4. Confirm that the NoDoc platform opens, then check the role or ownership indicator available in your tenancy. Use a contributor role to author; use a reader or reviewer role only for the review actions it exposes.
Task 2 · Open LiveLabs Focus Area
  1. Open the navigation menu and select LiveLabs Focus Area.
  2. Open the LiveLabs repo in that Focus Area and confirm that its content is visible. In this guide, “LiveLabs repo” means the NoDoc workspace content location; it does not require a local Git workflow.

Task 3 · Understand The Workspace Hierarchy
  • When navigating the workspace, use the following hierarchy: Focus Area → LiveLabs repo → Article → Article version (if available) → Page.

Task 3 · Delete An Article Or Page
  1. Confirm that you own the article or page and that deletion is authorized. Do not delete content that belongs to another author.
  2. Select the article or page in the table of contents, then click the trash bin icon at the top of the page.
  3. Read the confirmation dialog, verify the target, then select OK. The selected content is deleted; verify that it no longer appears in the table of contents.
Task 4 · Control Autosave
  1. Use the Autosave toggle in the page toolbar to choose whether NoDoc saves progress automatically.
  2. Turn Autosave ON when you want automatic progress saves. The current UI confirms that it runs every two minutes; when Autosave is OFF, automatic saves are disabled.
  3. Before leaving the page, confirm the saved state. Owners use Save to update the original; non-owners use Save Draft for owner review.

Task 6 · Write Structured Content
  1. Open the target page and select Edit.
  2. Confirm editing is enabled: the editor toolbar and Save & Check In are visible.
  3. Use the toolbar to build or revise the page. Start with a concise introduction, objectives, prerequisites when needed, then headings and numbered learner tasks.
    • Heading sets the page structure.
    • Bold, Italic, and Strikethrough apply emphasis or mark text for removal.
    • Quote and Note separate quoted material, warnings, decisions, or context.
    • Code block adds copyable code; Tabs separate different content; Quiz adds a knowledge check; Inline code formats commands or tokens.
    • Image and Link add approved media with alt text and tested relative links; Indent/Outdent changes block nesting.
    • Video, Table, and Lists add media, structured data, and learner steps; MD Source lets you inspect or edit the Markdown source.
  4. Click Save & Check In to save progress manually, then review the rendered content, links, images, and page position.
Task 7 · Versioning
  1. As the article owner, select the article, choose Create Version, enter the agreed version label, then select Create Version.
  2. Confirm that the new version appears under the article before making substantial changes.
  3. Restore only when needed: choose Restore Article Version, select the exact target version, then select Restore after verifying it.
Task 8 · Manage Co-Authors
  1. Only the owner can change co-author access. Open the workshop article you own and choose Manage Co-Authors.
  2. Review the current co-author list before changing access.
  3. Choose Add Coauthor to grant approved collaboration access.
  4. Select a co-author and choose Remove Coauthor only when their access should end.
Task 9 · Add A Comment
  1. Open the page in edit mode and select the exact text that needs feedback.
  2. Select the Comment control. In the dialog, enter concise feedback and the required Comment Email, then select Save Comment.
  3. Confirm the Content saved successfully!!! message and that the selected passage remains highlighted as the comment anchor.
  4. Use My Comments to return to a comment; choose Show All Comments when you need the wider page discussion.

Use these controls only when the approved workflow needs an OraHub repository copy. They are separate from the standard NoDoc-to-WMS publishing route.

Objectives

  • Load approved OraHub Markdown into a selected NoDoc page.
  • Export reviewed NoDoc content to the approved OraHub branch when required.

  1. For a new page, use the Import From OraHub creation option in Lab 2.

    For an empty or existing selected page, use the upper action-row From OraHub control.

Lab 4 · AI Assistance, Codex Skills, And Information Maps15 minutes

Use NoDoc AI assistance to improve an author-reviewed draft, use available focus-area Codex skills for analysis, then generate an article Information Map only after the page set is complete.

Objectives

  • Run a standards or persona-based AI correction.
  • Inspect differences before overwrite.
  • Run an available focus-area Codex skill on selected content.
  • Generate an information map from the article's first page.
Task 1 · Run AI Correction Safely
  1. Open the Author page as its owner.
  2. Use the upper action-row Vibe Doc-ing control, then select the action that matches the need: Apply Standards, a supported persona extraction, a custom prompt, or a checklist available in the current UI.
  3. Review the generated content and open the difference view before making any replacement.
  4. Reject unsupported changes. Keep only improvements that preserve the approved technical meaning, required metadata, links, code behavior, and safety or review constraints.
  5. Use Overwrite only after human review, then save and recheck the rendered page.
Task 2 · Try An Inline Correction
  1. Select one sentence on the page.
  2. Right-click and choose Vibe Doc-ing.
  3. Select Formal, Heading, or a custom prompt when that action is available.
  4. Review the result, edit it if needed, and replace only the selected text if it is accurate. Save the page after the change.
Task 3 · Use A Focus-Area Codex Skill
  1. Open the Codex control at the Focus Area level, if your role and tenancy show it.
  2. Use Open All or Close All to choose only the articles and pages that need analysis.
  3. Run only a skill available in that UI. The accessible source material documents a Grade skill that analyzes selected pages and produces recommendations.
  4. Review the result and, when offered, download its CSV report. Treat recommendations as review input; they do not automatically modify the pages.
Lab 5 · Ingest And Ask NoDoc15 minutes

Make approved content available to Ask NoDoc, then constrain a question to the right Focus Area, article, and version.

Objectives

  • Ingest a page or article deliberately.
  • Select a focused Ask NoDoc context.
  • Check that answers remain grounded in workshop content.
Task 1 · Ingest Approved Content
  1. As the owner, confirm that the selected page or article is saved, technically reviewed where required, and safe to make available for retrieval.
  2. Select the exact page or article and choose Ingest from the upper action row. NoDoc chunks and vectorizes that selected content for retrieval.
  3. Wait for the ingestion status to complete, record the scope and timestamp, then ask a question that the ingested content should answer.
  4. If the result is not available, first confirm the selected scope, current version, and completion status. Do not repeatedly ingest or broaden the scope without understanding what changed.
  5. Ingest a new article version after its content is ready; it is not added to the retrieval scope automatically.
  6. Do not ingest confidential, secret, or unapproved production content into a shared test or authoring flow.
Task 2 · Open Ask NoDoc And Ask A Focused Question
  1. Open Ask NoDoc from the upper-left action menu or the bottom-right chat button shown in your environment.
  2. Choose Focus and select NoDoc. Use the unfiltered option only when the wider NoDoc collection is genuinely needed.
  3. Narrow the context in order: Focus Area, article, then release version.
  4. Ask a question answered by the Prepare page.
  5. Inspect the answer and source or link context. Tighten the focus if the answer mixes content from an unintended article or version.
  6. Use the selected-articles or filter indicator, when shown, to inspect or remove active filters before starting an unrelated question.
Lab 6 · Quality Assurance, Review, And Publishing Request15 minutes

Create the article in NoDoc, copy its current preview link, complete the Quality Assurance checklist, and wait for WMS review. Create the publishing request only after WMS status is Completed.

Objectives

  • Use the NoDoc preview link to check the final article.
  • Complete the Quality Assurance checklist and resolve review comments in NoDoc.
  • Create the WMS publishing request after review is complete.
Task 1 · Check The NoDoc Article
  1. Confirm metadata, page order, links, code blocks, images and alt text, and rendered content in the current NoDoc preview.
  2. Copy the preview link and add it to the Self Quality Assurance checklist.
  3. Save the checklist and move the workshop to Self Quality Assurance Complete.
Task 2 · Wait For Review
  1. Wait for WMS review rather than creating a separate review document.
  2. Resolve requested changes in NoDoc, update the preview link if needed, and repeat the Quality Assurance checks.
  3. Continue only when the reviewer has moved the WMS status to Completed.
Task 3 · Create The Publishing Request
  1. In WMS, open Publishing and click Publish to LiveLabs.
  2. Enter the approved production location for the final workshop instructions, choose the required publishing options, and create the request.
  3. Save and confirm Publish Requested. Configure Sandbox Environment only when the workshop needs a LiveLabs sandbox.
