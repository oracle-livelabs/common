Introduction · No Doc One ToolWorkshop orientation

No Doc is an Oracle APEX documentation workbench for creating, organizing, reviewing, improving, ingesting, and preparing technical content for publication. In this workshop, you build a small documentation set, collaborate through drafts and comments, apply AI-assisted corrections with human review, generate an information map, ingest content for Ask No Doc, and complete a controlled pre-publish review.

Prerequisites

  • Oracle SSO access to the No Doc environment.
  • A No Doc role: CONTRIBUTOR for authoring or READER for review-only activities.

Objectives

  • Navigate No Doc and select the correct Focus Area.
  • Create an article, version, and page set for a documentation topic.
  • Edit content, apply metadata, and use supported editor features.
  • Collaborate with comments and draft review without overwriting original content accidentally.
  • Apply AI-assisted correction and generate an article information map with explicit human review.
  • Ingest and query approved content with Ask No Doc while inspecting source context.
  • Prepare a controlled preview while keeping release ownership and approvals explicit.
Lab 1 · Access And Navigation10 minutes

Connect to NoDoc, sign in, and open the LiveLabs Focus Area used throughout the workshop.

Objectives

  • Sign in through Oracle SSO.
  • Navigate the NoDoc platform.
Task 1 · Reach No Doc Platform
  1. Open the approved NoDoc environment. Open NoDocRequires Oracle VPN and NoDoc access.
  2. Sign in through Oracle SSO. If the stage environment requests a bypass code, obtain it through the approved manager process; do not paste codes into workshop artifacts.
  3. Click on "No Doc" option.
  4. Confirm reaching the "No Doc" platform.
Task 2 · Open No Doc Repo
  1. Open the hamburger menu.
  2. Select No Doc Repo.
  3. In No Doc Repo, select the LiveLabs Focus Area.
  4. After selecting it, confirm that the LiveLabs Focus Area opens and its content is visible.
Lab 2 · Authoring And Structure20 minutes

Create a versioned article and page set, then add metadata and structured content that can be reviewed, ingested, and published later.

Objectives

  • Create an article from scratch.
  • Add pages at the correct TOC location.
  • Use metadata, links, code blocks, notes, and supported editor features.
Task 1 · Create The Article Shell
  1. In No Doc Repo, click the + icon beside the selected Focus Area.
  2. Choose Article.
  3. Enter a name such as No Doc Workshop Practice and a version such as 2026.08.
  4. Choose Create From Scratch, then create the article.
  5. Leave the article's first page reserved for metadata and the later information map.
Task 2 · Add Pages
  1. Click + beside the article or an existing page.
  2. Choose Page and create pages named Prepare, Author, and Review.
  3. Confirm that pages appear under the intended article.
  4. Add metadata tags at the top of each page, including product, release, topic type, and audience.
Task 3 · Add Structured Content
  1. Edit Prepare and add a short introduction, objectives, and prerequisites.
  2. Add a numbered procedure, a note, a link, and a code block.
  3. Use Markdown source mode to inspect the generated content when available.
  4. Save the page and verify that the TOC and content remain aligned.
Lab 3 · Review And Drafts15 minutes

Use comments and drafts to collaborate without changing source content until the owner approves the change.

Objectives

  • Add an anchored review comment.
  • Create and inspect a draft.
  • Review differences and apply an owner-approved overwrite.
Task 1 · Add A Comment
  1. Open the Prepare page in view or edit mode.
  2. Select a sentence that needs clarification.
  3. Add an inline comment with a specific, actionable suggestion.
  4. Save and confirm the comment is anchored to the selected text.
Task 2 · Create A Draft
  1. Sign in as a non-owner reviewer, or use the supplied reviewer account.
  2. Open the commented page and click Edit.
  3. Accept the prompt to work on a draft.
  4. Improve the selected sentence and save the draft.
Task 3 · Review And Approve
  1. Sign in as the page owner.
  2. Open Drafts and inspect the pending draft.
  3. Use View Diff to review each change.
  4. Accept or reject changes individually.
  5. Approve and overwrite only after confirming the final content.
Lab 4 · AI Correction And Information Maps15 minutes

Improve a page with AI-assisted tools while preserving human review, then generate an article information map after all pages exist.

Objectives

  • Run a standards or persona-based AI correction.
  • Inspect differences before overwrite.
  • Generate an information map from the article's first page.
Task 1 · Run AI Correction Safely
  1. Open the Author page as its owner.
  2. Choose Vibe Doc-ing and select Apply Standards or a supported persona extraction.
  3. Review generated content and open Difference.
  4. Reject unsupported changes; keep only improvements that preserve technical meaning.
  5. Use Overwrite only after human review, then save.
Task 2 · Try An Inline Correction
  1. Select one sentence on the page.
  2. Right-click and choose Vibe Doc-ing.
  3. Select Formal, Heading, or a custom prompt.
  4. Review the result and replace only the selected text if accurate.
Task 3 · Generate The Information Map
  1. Confirm that all workshop pages exist and are saved.
  2. Open the first page of the article as the owner.
  3. Choose Generate Information Map.
  4. Confirm that page summaries and source links are generated while metadata remains intact.
Lab 5 · Ingest And Ask No Doc15 minutes

Make approved content available to Ask No Doc, then constrain a question to the right Focus Area, article, and version.

Objectives

  • Ingest a page or article deliberately.
  • Select a focused Ask No Doc context.
  • Check that answers remain grounded in workshop content.
Task 1 · Ingest Approved Content
  1. Confirm that the article content is approved and saved.
  2. Select the article or a page and choose Ingest.
  3. Wait for ingestion to complete; record status and timestamp.
  4. Do not ingest production or confidential content.
Task 2 · Ask A Focused Question
  1. Open Ask No Doc from the application menu.
  2. Choose Focus and select NoDoc.
  3. Narrow context by Focus Area, article, and release version.
  4. Ask a question answered by the Prepare page.
  5. Inspect the answer and source/link context; tighten focus if needed.
Task 3 · Search And Export
  1. Use metadata select-and-search or Vibe Searching to find a workshop page.
  2. Start a new chat if you need a clean context.
  3. Download the current chat JSON only to the approved local test location.
Lab 6 · Pre-Publish And Release Handoff15 minutes

Prepare a publish preview and hand off evidence without treating a preview as approval to release.

Objectives

  • Validate content before publication.
  • Generate a preview or package in the approved non-production path.
  • Record release evidence, ownership, and unresolved risks.
Task 1 · Run The Pre-Publish Checks
  1. Confirm required metadata, information-map content, links, code blocks, and page order.
  2. Review comments, pending drafts, and open review decisions.
  3. Confirm that no secrets or unsupported internal-only data are present.
  4. Check representative content in view mode and Markdown source mode when available.
Task 2 · Generate A Preview
  1. Open the applicable LiveLabs Pre-Publish or OHC preview flow.
  2. Select the workshop/article and version.
  3. Generate the preview or download package in the approved test target.
  4. Inspect rendered output, links, metadata, and navigation.
  5. Record preview location and defects; do not push to a production repository.
Task 3 · Complete The Handoff
  1. Record owner, reviewer, version, environment, preview evidence, and release decision.
  2. Link open defects or mark them as release risk.
  3. Obtain release-owner approval before any push or overwrite.
